# 应用显示大小

## 使用

设置 → 应用与小组件 → 应用显示大小，搜索并选择应用。浮窗启动器的应用操作菜单也有同名入口；原生卡片通过设置页配置，共用系统中的同一条应用策略。

页面优先展示模式切换、五档大小和高级参数。“清晰竖屏（实验）”连同说明放在常规设置及恢复操作之后、页末作用范围说明之前，两种模式均可向下滚动找到。

开启清晰竖屏后，其下显示“竖屏比例”四个 Tab：9:20、9:16、12:16、15:16（宽:高），默认 12:16。每个应用独立保存比例，关闭开关时隐藏选项并保留选择；恢复大小或接纳新基准不清除比例。切换仅保存配置，下次从本工具打开时应用，不提交尚未应用的 DPI/缩放草稿。旧记录未保存比例时同样使用 12:16。

四比例验证：`AppPortraitBoundsTest` 覆盖尺寸、真实缺口、宽度不足时等比缩小及非法比例拒绝；模拟器设置检查在正常和 200% 字体下各通过 79 项。SM-F731U1 直接运行 APK 内控制器，深蓝汽车四档任务分别确认 294×654、366×654、490×654、612×654，均为 portrait，结束后区域释放。未逐档重新验收键盘、弹窗和触摸；原始证据在 `Cache/tests/portrait-ratios/`。

首次进入应用配置时，已保存为“自定义”的参数默认显示高级模式，五档或默认值显示简单模式；首次系统读取也会核对这一选择。用户手动切换模式、导航返回或恢复页面时尊重其选择，刷新不会强行跳回高级模式。

- **简单模式**：横向五档 Tab「更小、较小、默认、较大、更大」。点击后保存一次，不显示 DPI。保持调整前的 DPI，主要改变分辨率缩放系数；窄屏可横向滚动，保留触摸尺寸。
- **高级模式**：保留五档入口，可填写自定义 DPI 和分辨率缩放系数，点击「应用设置」提交。编辑期间不写系统设置；切换模式保留输入，返回时可放弃未应用输入。高级自定义显示「自定义」，不会误选某个档位。
- **清晰竖屏（实验）**：两种模式共用一个开关，保持拿握方向，为应用提供竖向区域，内容由原 App 自行滚动。开启时仍采用 DPI、分辨率缩放和五档参数；关闭或恢复大小不清空另一项设置。开关保存后下次从本工具打开生效，不自动打开、强停或旋转应用。分辨率缩放低于 1 仍可能变糊；该开关解决布局问题，不保证所有参数和所有应用都清晰。
- **打开应用**：通过现有共享启动链路在所选外屏打开应用。未应用输入需要先应用；按钮就近说明只打开、不重启，不自动强停或清理任务。更改后先从最近任务关闭再打开；仍无变化时，用户可在系统应用信息中手动强行停止后重开（后台服务也会停止），不需要清除数据。
- **默认 / 恢复调整前的大小**：恢复首次调整前保存的该应用条目，原本没有条目时移除本工具添加的条目。不会用统一数字替代用户先前通过其他工具设置的值。

需要已授权并连接的 Shizuku、可用三星外屏和本版本能识别的 MultiStar 策略。应用需先加入 Good Lock → MultiStar → I ♡ Galaxy Foldable → 外屏启动器。助手只读取名单，不自动扩展名单、授权或修改整屏密度。

写入成功只表示系统设置回读核对通过，不代表已有任务已经重新采用策略。可能需要用户关闭应用后重新打开；部分三星固件移除最后一条策略后仍缓存原值，可能需要重启手机刷新。不能通过强停 System UI 或修改其他应用条目强制刷新。

## 参数与恢复基准

界面统一称为“分辨率缩放系数”，底层仍是三星的应用兼容缩放参数。它调整应用绘制画面的宽高，再由系统缩放到外屏，不改变面板的物理分辨率；这不是单独调字号。已验证固件下，0.5 会让绘制宽高各减半，像素总数降至四分之一，再放大显示，因此清晰度降低。重命名不改变参数范围、已有数值、恢复记录或写入协议。

建议参数集中在 `app-config.json` 的 `appearance.appDisplay`，由 `gradle/app-config.gradle` 生成并校验。四个快捷档位使用 0.8、0.9、1.1、1.2 的名义大小比例：保留恢复基准的 DPI，用原兼容系数除以比例并保留三位小数；默认直接恢复原条目。例如 480/2 的四档为 480/2.5、480/2.222、480/1.818、480/1.667。每次从原基准计算，不在上次点击结果上累积。已有显式策略优先，未找到时以配置文件的 480 DPI / 1.715 为建议起点。页面明确这是建议参数，不声称测得了原应用大小；OEM 内置应用策略也可能优先于 MultiStar。

集成 AndroidAutoSize 等自适配方案的应用可能按屏幕宽度重算密度，单改 DPI 不一定改变界面。设置页解释这一情况，简单模式不展示 DPI，高级模式提示尝试分辨率缩放。原系数为 1 时先按已识别固件的 DPI/340 特殊规则换算基准；超出安全边界不截断，提示使用高级模式。旧版五档保存的参数不自动改写；参数与新五档不匹配时显示“自定义”，原恢复条目和草稿继续保留。

高级 DPI 允许 120–960 的整数，兼容系数允许 0.50–4.00（不含 1），两者相除须在 120–960 范围内。边界属于本工具的保守校验，不宣称是三星系统极限。小于 1 可放大，代价是同屏内容减少、可能变糊。三星对系数 1 使用特殊分支，所以不把 1 当作普通编辑值；原有特殊参数仍可原样恢复。五档舍入恰好得到 1 时使用相邻普通值 1.001；超出可表达范围则提示使用高级模式，不静默截断。非法输入旁显示“未保存”及修正方向，不只在页末提示；例如 120/1.01 低于组合下限，会保留上次已保存值。

## 责任与事务

- `AppDisplayPolicy`：参数、档位、三星协议、单条条件替换及回滚。策略字段为 AES/CBC/PKCS5Padding + Base64 编码的包名、任务密度、兼容系数。
- `SystemAppDisplay`：在受限 `ShellService` 中校验三星能力、显示器、所属用户及名单状态。仅写 `Settings.Secure.multistar_cover_widget_policy_list`；其他 MultiStar 键只读。
- `SystemAppPortrait`：受限服务内创建并拥有一个仅属于所选三星外屏的 TaskDisplayArea，以局部坐标设置竖向区域并定位其 SurfaceControl；原应用在区域内全屏运行，保留三星应用缩放。只允许目标包的标准启动入口，不接收任意 Intent、Shell 或输入事件。`AppPortraitBounds` 根据物理模式、当前旋转和真实缺口计算区域。
- 竖屏比例由同一恢复记录的 `portraitRatio` 字段保存，经共享 `AppLauncher` 传入服务；服务只接受四种比例。区域按比例完整放入真实缺口安全矩形并居中，宽度不足时同时减小高度，不拉伸；尺寸向下对齐偶数像素，会有不足 2 像素的比例取整误差。748×720、底部缺口 66 像素时四档依次为 294×654、366×654、490×654、612×654，默认使用 490×654，替代早期固定 620×654。
- `AppDisplaySettings`：模式、草稿、读写反馈和恢复。`Prefs.app_display_sizes` 是本地恢复基准与事务记录唯一来源，不另建偏好文件。
- `SettingsApplications` / `SettingsNavigator`：复用应用目录、搜索、列表位置、按应用路由身份及草稿恢复，调整过的应用优先显示。

首次修改前同步保存原条目、上次确认条目、目标条目和设备/用户上下文。写前复读比对选中应用并合并其他应用的最新条目，写后回读；失败只在目标仍等于本次写入值时尝试回滚。Settings 没有跨应用原子 CAS，最后检查与提交之间仍可能遇到其他工具竞争，不能宣称全局事务隔离。

迟到回调只完成本次本地记录，不恢复旧页面；中断遗留的 pending 记录在下次读取时核对。外部修改导致冲突时停止覆盖，提供需明确确认的「以当前设置作为默认」。系统策略和恢复记录不进入配置导入导出或布局备份。已卸载应用保留恢复入口，不当作可启动应用。

当前适配仅接受与已分析三星框架一致的内置外屏 1、已有新版 legacy repository 和对应协议。不因任意副屏存在就宣称支持，不回退主屏。`AppLauncher` 是两个宿主的唯一启动路由：普通模式沿用默认 ActivityOptions；清晰竖屏指定自有区域和全屏窗口模式，不添加会跳过 MultiStar 策略的 `setCustomizedCoverDensity(-1)`。

开关在同一条 `Prefs.app_display_sizes` 记录的 `portrait` 字段保存，不复制 DPI 或系数；设置冲突接纳新基准时保留开关，设置列表计数和排序包含已启用开关。区域一次只存在一个，显式启动替换上一会话；关闭、失焦、任务退出、息屏、锁屏或显示器身份/方向改变时释放。只在会话内注册显示器与任务栈事件，启动后一次有界稳定检查，此后无轮询。清理仅删除自有区域并释放订阅、回调和 SurfaceControl；系统接管原任务，不清应用数据。请求失效后的回调按会话标识清理，不能关闭更新的会话。服务 Binder 死亡由系统回收其拥有的区域。

## 验证边界

`AppDisplayPolicyTest` 覆盖参数边界、档位顺序、特殊系数、协议、原条目恢复、其他条目保留、冲突、写入拒绝、回读不一致及目标失效。

模拟器场景 `app-display-size` 使用隔离副屏和内存服务，不写真实三星设置；检查模式切换、五档/自定义、草稿、恢复、冲突、迟到回调和本地记录。Cache 中的原始截图仅供验证。

真机待验：MultiStar/OEM 优先级、五档视觉顺序、新旧任务、清空最后一项的系统缓存、打开查看效果、两种启动器入口、键盘、内外屏切换、锁屏、授权撤销和固件升级。模拟器通过不替代三星固件验收。

2026-10-12 在 SM-F731U1 的深蓝汽车主页面做单应用策略对照，经用户允许强停后重新启动并等待主页面：系数 1.5 固定，DPI 480→720 时文字和图标几乎不变；DPI 480 固定，系数 1.5→3.0 时文字和图标明显缩小。系统任务配置确认采用了两组系数。测试结束恢复原策略并重新打开，完整策略回读与测试前一致。此证据验证兼容缩放路线，不代表所有页面、应用或五档参数均已通过真机验收；3.0 过小，不作为固定快捷档位。原始证据位于 `Cache/tests/atian-4.41-scale/`。

同日补验低于 1 的范围：保持 480 DPI，系数 0.9、0.75、0.5 均进入系统任务配置，最终物理缩放分别约 1.111、1.333、2.0；0.5 主页面文字和图标明显放大，同屏内容减少并出现放大模糊。测试后完整策略恢复为测试前的 480/1.01，应用本地 applied 记录继续匹配。没有触发车锁、空调等实际车辆操作；这些操作、其他页面的触摸及其他固件未验证。原始证据位于 `Cache/tests/app-display-size/under-one/`。

## 保持拿握方向的清晰竖屏：真机研究结果

2026-10-12，SM-F731U1、深蓝汽车 1.10.2（1914）、外屏 1 的研究验证。用户要求完整使用原 App、允许滚动，并明确保持当前拿握方向。以下是早期路线对照；正式开关采用后续区域方案。

| 路线 | 观察结果 | 判断 |
| --- | --- | --- |
| 当前 240 DPI / 0.75 | 561×540 的应用画面经约 1.333 倍放大显示 | 有放大画质损失 |
| 240 DPI / 1.001、外屏 0° | 接近原生像素，界面仍小 | 清晰度与布局是两件事 |
| 同参数、外屏 90° | 实际配置切为 portrait，文字明显变大；两次冷启动复测一致 | 技术有效，但用户不接受转动手机 |
| 自由窗口 748×1600 | 系统接受窗口，原生绘制清楚 | 尚不能完整浏览窗口 |
| 将长窗口 top 设为 -500 / -880 | am 命令拒绝负坐标；直接调用 resizeTask 也被系统调整回 top=0 | 不能把任务移动当作可用的长画布滚动方案 |
| 仅缩窄自由窗口至 600×654 / 540×654 | 任务为竖向，Activity 实际配置却仍可为 landscape，文字依旧很小 | 只改窗口几何不足以解除三星兼容策略 |
| 原生密度启动 + 620×654 竖向自由窗口、外屏 0° | Activity 实际配置为 340 DPI、portrait，绘制尺寸与窗口尺寸一致，不再放大低分辨率画面 | 用户现场确认“文字清楚，可以正常上下浏览” |

有效实验通过 `ActivityOptions.setLaunchDisplayId(1)`、自由窗口模式 5、`setLaunchBounds(Rect(64, 0, 684, 654))` 和三星的 `setCustomizedCoverDensity(-1)` 启动原 App。后者在已分析固件中走原生外屏密度路径；与阿田参考启动代码使用的参数一致。必须区分“阿田的启动参数可作为线索”与“阿田已提供并验证了同样的小窗产品功能”，此次只验证了前者的可用组合。窗口仍属于原 App，使用系统原生触摸路由；未注入输入、读取页面节点、修改 APK 或操作车辆功能。

仅创建了临时 ADB 验证程序，没有向主应用增加任意 Shell 或启动能力。实验过程中单应用策略均按目标条目核对并恢复，未改动其他应用策略、内屏分辨率或外屏物理尺寸；最终保存的策略仍为测试前的 240/0.75，方向仍为 lock 0。用户确认后保留当前清晰小窗供继续体验，手机上的临时验证程序已删除。

后续用户要求开启时也能继续调整大小，因此未采用上述原生密度自由窗口路线。新的专属 TaskDisplayArea 在外屏中使用 620×654 的局部区域，SurfaceControl 定位到 x=64；应用仍以全屏任务在该区域运行。真机 480 DPI / 0.75 和 480 DPI / 1.5 分别得到 465×490 和 930×981 的绘制尺寸，证明分辨率缩放继续参与；1.001 接近原生绘制。用户手动点击“服务”再返回“爱车”并滚动，确认“点击准确，滚动正常”。未操作车辆控制。原始证据位于 `Cache/tests/deepal-portrait-area/`。这份原型证据不替代正式开关及完整生命周期验收。

尚未验收：登录/键盘、弹窗和子 Activity、多页面跳转、车钥匙后台、锁屏与内外屏切换、其他固件，以及从本工具两种启动器入口反复切换显示方式。当前证据只证明这台手机上主页面显示与用户手动滚动可行，不能称为所有 App 的通用完美适配。

原始记录位于 `Cache/tests/deepal-native-window/`；本地真机对照图为 `dist/app-display-size-study/comparison-framed.png`，左侧是原 240/0.75 全屏，右侧是原生密度竖向小窗，使用同等屏幕像素比例并各叠加一次标准设备贴图。

正式代码验证：`AppPortraitBoundsTest` 检查自然方向、反向及旋转后的真实缺口避让和非法空间拒绝。模拟器 `app-display-size` 在正常与 200% 字体下通过 60 项检查，涵盖开关保存不写缩放、切换不提交草稿、恢复大小保留开关；`app-launch-reuse` 通过 32 项普通启动回归。通过临时 ADB 驱动直接运行 APK 内的 `SystemAppPortrait`，确认真机启动稳定后区域仍有效；转到三星首页后区域已释放。曾发现不同区域的首页可在旧区域下方恢复，已用任务前置事件补足清理，复测通过。此证据不包含正式安装后两宿主的手动点击、键盘和锁屏全流程，继续按实验功能交付。证据在 `Cache/tests/deepal-portrait-switch/`。
