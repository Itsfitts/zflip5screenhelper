# 模块契约

本文件保存从 AGENTS 拆出的详细模块约束，供对应模块的实现与评审查阅。协作总则见 [AGENTS](../AGENTS.md)，构建与验收入口见[开发说明](development.md)。修改模块前读取相应章节及其链接的专题文档；用户当前指令与协作总则优先。历史发布记录中的旧行为不覆盖当前契约。

## 配置与在线更新

- 工程检查不依赖正式签名密钥；所有可安装 APK/AAB 仍使用唯一正式签名并在缺失配置时拒绝打包。Gradle 管理版本与依赖，`tools/project/` 校验仓库、网站和真实 APK，版本目录禁止覆盖；单人 main 提交和发布边界见 `docs/engineering-workflow.md`。普通 CI 不使用正式私钥；版本标签通过独立环境执行正式签名，校验同次产物后发布 GitHub 预发布包，签名作业无仓库写权限。

- 根目录 `app-config.json` 仅集中常用可调参数，按 `update`、`defaults`、`appearance`、`motion` 分组，修改后重新构建生效；字段校验与常量生成由 `gradle/app-config.gradle` 管理。新增常用调节项优先接入此文件，不要求所有配置集中：包名/版本/SDK/依赖留在 Gradle，固定网格与安全约束、内部缓存上限和算法细节留在所属模块，签名密钥独立保存。用户已保存的偏好优先于 `defaults`；共享样式类继续负责计算及双宿主适配，生成常量/资源不作为第二份配置源。使用说明见 `docs/app-configuration.md`。

- `AppConfig` 读取统一开发配置；`UpdateCatalog` 校验服务端协议和项目内路径，`AppUpdater` 管理页面范围内的检查、流式下载、文件与签名证书校验及取消，`UpdateSettings` 提供关于页交互。仅用户发起更新时联网，系统确认安装，不自动授权或静默安装；发布产物由 `:app:prepareUpdateRelease` 生成，协议与验证见 `docs/online-update.md`。

- 今后主应用 APK 统一按类型和版本号交付：Release（含更新测试基线）放在 `dist/update-release/<versionCode>/`，debug 放在 `dist/update-debug/<versionCode>/`；分别命名为 `flipcover-<versionName>.apk`、`flipcover-<versionName>-debug.apk`，同目录提供依据该 APK 实际元数据、大小及 SHA-256 生成的 `catalog.json`。`Cache/` 仅存构建中间产物，不作为最终交付入口，不再将新 APK 散放于 `dist/` 根目录；历史产物不自动搬移。测试低版本只临时覆盖构建版本，不降低项目正式版本或覆盖已发布版本目录。打包检查与目录规范见 `docs/online-update.md`。


## 设置与外接输入

- 外屏入口打开助手设置时，为所选显示器使用固定的 `MainActivity` document 身份，重复打开复用同一任务；内屏普通设置入口及其他副屏的 document 身份独立。若系统曾迁移该外屏任务，再次显式打开时仍指定原目标外屏，不回退主屏。复用时接收新的页面及应用参数，同一页面保留当前状态，未保存的草稿在跳转前由用户确认放弃，返回时不恢复已放弃的草稿；不自动清理历史任务或影响原生卡片配置会话。

- 应用显示大小中的“清晰竖屏（实验）”由同一恢复记录保存开关，开启时仍采用 DPI 和分辨率缩放；`AppLauncher` 统一两宿主路由，`SystemAppPortrait` 只拥有所选外屏上的专属任务区域。失焦、关闭、息屏、显示身份变化和服务结束释放区域及事件订阅，不轮询、不注入输入、不改变整屏方向。详细边界见 [应用显示大小](app-display-size.md)。

- “应用显示大小”提供简单/高级双模式：简单模式五档 Tab 保持原基准 DPI、通过分辨率缩放系数调整；高级模式编辑 DPI 与分辨率缩放系数，切换模式不写系统设置；自定义及旧版不匹配的档位参数不伪装成新预设。页面说明 AndroidAutoSize 自适配可能抵消 DPI 调整，并区分保存、普通打开与手动重新启动，不自动强停应用。`AppDisplaySettings` 管理页面，`Prefs.app_display_sizes` 保留仅本机的恢复基准与 pending 记录；`AppDisplayPolicy` 管理参数和单条条件更新，`SystemAppDisplay` 经 `ShellService` 白名单仅修改选中应用外屏策略，不自动修改 MultiStar 名单、授权或整屏 DPI。写前后校验、冲突停止覆盖和恢复边界见 [应用显示大小](app-display-size.md)。两宿主复用已有 `AppLauncher`，原生卡片从设置页配置。

- “问题诊断”进入页面及点击“刷新日志”时按当前状态重新采集，并标明采集时间；原位更新摘要与原始详情，保留滚动和详情展开状态，不增加后台轮询。刷新清除旧 Shizuku 补充结果，之前请求的迟到回调不能覆盖新批次；Shizuku 检测开始时同样重新采集本地状态和当前目标。复制同步显示同一份结果并附最新内存启动记录，不写入磁盘或上传。
- 省电诊断区分 `PowerManager.isPowerSaveMode()` 的有效策略读数与 `Settings.Global.low_power` 的标准配置，不据此断言三星设置开关的实际位置。用户发起 Shizuku 检测时，用固定只读 `dumpsys power` 独立采集有效策略、full、adaptive、advertise 和服务侧标准配置；仅输出这些布尔字段，不返回完整电源转储中的其他应用信息。缺失或固件格式不支持明确为未知；该检测不修改省电配置，也不改变玻璃准入策略。

- 设置首页底部说明以当前应用版本号开头，读取 Gradle 自动生成的 `BuildConfig.VERSION_NAME`，不另存或硬编码版本值。

- `MainActivity` 负责设置路由与配置交互；`SettingsUi` 提供设置专属主题与事务滑条，`SettingsNavigator` 保存有界来源栈和条目锚点，`SettingsApplications` 复用应用目录并随挂载订阅，`SettingsIllustration` 绘制本地示意。设置更新不得通过全局修改 `Ui` 改变运行时悬浮层。主设置页与自有设置弹窗共用 `SettingsUi.Viewport` 基础缩放及本机70%–130%调节；组合卡片配置及其全部子页保持既有尺寸，不接入该缩放。

- 设置首页底部“检查更新”旁的“兼容性说明”、“应用 Dock 与中心”底部与“问题诊断”的相关入口共用 `launch_compatibility`“兼容性说明”只读页；首项“测试机型”展示“三星zFlip5,OneUI8.5,其他版本出现bug请及时反馈.”，其余简短条目说明阿田手势后台、原生卡片编辑、系统最近任务授权与固件兼容性和受保护任务预览。设置搜索覆盖条目名称、阿田自用/辅助、快捷手势及“打开手机以继续”。只展示有依据的限制及处理方式，不主动弹窗、不更改第三方设置或系统放行列表；返回沿用来源栈。

- `SettingsOrderList` 提供带图标的单行快捷项草稿列表、拖拽落点与边缘滚动、移除撤销及无障碍排序。拖动只提示落点，放下才修改草稿，移出列表放下或离开页面取消；页面卸载停止滚动回调。`MainActivity` 保存草稿与撤销状态，只有“完成”写入偏好，返回可放弃。

- `InputDevices` 负责事件驱动设备发现与本机配置，`InputSurface` 统一自有窗口内六键、模态范围和快捷栏直达；`InputNavigation` 维护稳定目标、页面区域及有界会话焦点。基本导航不引导进入控制中心、启动器及复杂布局编辑；短取消逐层返回，长取消/F6直达快捷栏，取消不暂停设备规则。文本输入保留光标操作，设备断连、窗口失焦和卸载取消旧输入。`NativeCardInput` 仅在所选外屏解锁且桥接器确认唯一可见卡片时复用已发布的 RemoteViews 与原有点击权限；集合使用有实例身份的 `AppWidgetHostView`，顶层取消后等待新的可见会话再接管。不读取其他应用节点树、不向系统注入输入、不新增 root 或驱动依赖；设备身份不进入备份。边界见 `docs/external-input.md`，各页操作及验收见 `docs/six-key-navigation.md`。

- 设置界面的设计、重构、原型和评审使用项目 Skill：[oneui-settings-design](../.agents/skills/oneui-settings-design/SKILL.md)，并按其协作规则参考已安装的 `mobile-android-design`。设计规则和九张原样参考图由项目 Skill 维护，页面迁移方案见 [设置 UI/UX 重构方案](settings-ui-refactor-plan.md)；不将设置主题自动扩展到运行时悬浮层或系统选择器。


## 控制中心

- `RotationControls` 是快捷栏全屏旋转页与控制中心旋转详情的唯一正文组件；按控制中心详情统一为自动旋转行、横向四角度胶囊、左右反向行与说明，交回系统按钮使用相同文案和动作。`Panels` 与 `ControlDetails` 仅适配全屏／弹窗容器和关闭行为，不再各自维护方向网格或开关逻辑。

- `CoverRotation` 区分用户开启状态与传感器运行状态：息屏、所选外屏未亮起或锁屏仅暂停传感器，取消候选方向及旧异步工作，保留本次服务内的开关与握持方向校准；同一外屏亮起且解锁后，沿现有显示器／解锁事件恢复传感器，以新读数决定方向，不后台轮询。手动锁定、交回系统、助手停用、Shizuku 断连、所选显示器丢失／切换及服务销毁仍关闭自动旋转；不跨服务重启恢复，不回退主屏。排队命令执行前重新校验会话，迟到结果不能关闭或恢复新的旋转会话。

- 自动旋转请求2秒传感器采样间隔，首个有效读数及时接收，后续方向判定至少间隔2秒；系统提前送来的变化只保留最新角度及一个待处理回调，不建立空转定时器。每次开启／恢复创建新的方向监听器，拒绝旧监听器迟到读数，避免框架缓存吞掉相同握持角度的首个读数。传感器回调不重新枚举外屏或查询锁屏；生命周期事件及命令提交、执行前仍完整检查所选外屏。Shizuku 忙碌保留开启状态，每个目标方向最多重试3次、间隔2秒，耗尽后等待新的目标方向或会话恢复；断连及真实失败仍按既有规则关闭。独立旋转页与控制中心详情共用副标题，开启为“已开启 · 所选外屏 (2秒轮询)”，关闭为“已关闭 · 所选外屏”。

- 独立旋转页与控制中心旋转详情共用“左右反向”兼容开关，默认关闭，仅保存在本机，不导出、不随配置导入覆盖。仅在系统90°／270°时，优先把快捷栏移到对角位置（左上／右下、右上／左下互换）；目标区段必须位于安全区外，无法容纳时仍按安全区管理器选择真实外侧区段，不得挤入正文；双白条直接使用 `Prefs.entryPosition(rotation)` 保存的位置，不随此开关换边，0°／180°保持原布局。自动缺口定位与手动停靠都经过同一几何计算，真实缺口不镜像，换边后继续避让缺口与系统导航。切换立即刷新布局并保留旋转页面；不下发旋转、不改方向高亮、传感器校准或应用方向规则，不改写已有四方向位置偏好。

- 自动横屏定位的候选位置基准固定为正常布局：关闭时系统90°左上、270°右下，开启时90°右下、270°左上；最终位置再服从安全区外侧约束。不能直接把固件报告的缺口尾部所在侧当作“关闭”的位置，否则改装机可能把开关效果颠倒；仅调整快捷栏所在侧，安全计算仍使用真实缺口。设置预览使用同一角度与开关映射，电脑投屏旋转角度不参与应用布局。

- 手动定位及自动定位未选中缺口尾部时，先检查目标快捷栏矩形是否真正与缺口相交；能完整放在突出区域内时保留贴边位置，与原翻页点相邻，不因同侧另一段的缺口整体内移。确有相交时继续使用安全矩形避让；用户导航避让仍独立生效，双白条位置不变。

- Wi-Fi、蓝牙读取系统服务的实际状态，不把持久配置值当作无线电状态；切换中或接口拒绝时保持未知。移动数据绑定当前有效数据 SIM 的用户开关，读写前后复核同一订阅，不代表已联网，也不回退其他 SIM。五个基础开关（含勿扰、飞行模式）点击时重新读取再切换，写后有界确认；不根据缓存高亮反转。仅在控制中心或相关详情可见时订阅变化：应用进程观察相关系统设置并接收 Wi-Fi／飞行模式广播，受限 Shizuku 服务订阅蓝牙专用状态回调，卸载释放；刷新合并、忙碌重试有上限，旧面板、旧显示器和旧读取回调不能覆盖当前界面。

- 控制中心区分开启、关闭、未知与执行中；普通应用及一次性动作不显示开关状态。没有专门回读适配的应用磁贴初始就显示未知标记，点击转发不推断成功或反转高亮。旋转按钮区分工具自动旋转、已确认锁定、系统接管及未知，工具自动旋转停止时立即更新界面；交回系统不能标为锁定。内置状态和原应用磁贴状态不互相猜测或串用。

- “定位”是 `ActionCatalog` 的统一动作，快捷栏、控制中心和启动器侧栏共用 `CoverService.locationAction`，不分别保存开关值。`SystemLocation` 只管理所属 Android 用户的整机定位总开关，不采集坐标、不申请定位权限或改变其他应用授权。点击由受限 `ShellService` 读取当前值再切换，固定用户身份，写后读取确认；未知状态不猜测，系统拒绝或未确认时不得提示成功。控制中心与详情按可见挂载订阅定位广播并读取真实状态，卸载释放，不后台轮询；请求检查所选外屏及锁屏状态，旧会话回调不能恢复界面。已有列表不自动插入，新配置的控制中心默认包含定位，三个位置均可通过既有编辑器添加。

- 正常控制中心顶栏仅保留编辑与刷新；编辑由 `CoverService` 在原面板内打开 `ControlEditorView`，添加在编辑器内进行，不启动设置 Activity。`ControlEditGrid` 展示至多30项已选网格，`ControlCandidatesView` 虚拟化三来源候选网格，两区共用 `ControlEditGrid.columnsForWidth`，按编辑区实际可用宽度自动紧凑排布并独立滚动，不读取或改写正常控制中心的 `Prefs.panelColumns`。控制中心支持跨区拖入添加、拖回移除、网格排序、空位预览及撤销；草稿只在有效放下后变更，取消/多指/尺寸变化终止拖动，只有完成才写偏好。候选目录仅在相应页面挂载时订阅，卸载停止工作；外部配置变更不得静默覆盖。同一外屏重建可恢复内存草稿，关闭、息屏或切换目标外屏释放。编辑期间卸载媒体控件与订阅，`PanelSurface` 不抢编辑区域手势；图标沿用 `ActionCatalog`，设置页保留 `SettingsOrderList` 单行编辑。

- 正常控制中心（不含编辑页）列数由 `Prefs.panelColumns` 统一管理，默认4列，仅允许 3/4/5；旋转不切换列数，可视网格固定4行，少项留空位、超出独立向下滚动，图标与格位尺寸不得随按钮数量变化。`Panels.ControlDashboard` 的“自动／侧边”四方向均保持左右结构，亮度与音量在侧栏上部、媒体在下部；窄安全区优先压紧侧栏宽度和间距，保留左右手选择，仅显式选择“下方”或没有网格按钮时使用上下结构，不改写用户配置或显示器 DPI。配置导出与布局备份均包含列数，旧配置恢复4列默认值。

- 控制中心、编辑／候选搜索、控制详情、媒体内容及设置内布局预览使用 `PanelUi.controlContext` 的局部字体配置：字号倍率固定1倍、标准字重调整固定0、主题明确使用 sans-serif。文字创建和后续调字号统一经 `Ui.textSize`，仅控制上下文使用 dp 换算像素，避免重新走 SP／scaledDensity；其余页面仍使用 SP。Canvas 提示直接按真实密度绘制。系统字体大小与粗体不参与标签行数、图标大小或工具区排布；应用自己的字号、疏密、列数及真实外屏密度仍生效。容器、正文和详情子组件必须传递同一类局部上下文，不从服务上下文重新引入系统字体配置；通知页、普通设置页、启动器与系统选择器保留各自规则。不得修改系统字号、显示器 DPI 或改变 `Ui` 对其他页面的字号行为；三星替换字体的实际字形仍须在固件上验收。验证入口见 `docs/development.md` 的 `control-typography`。

- 控制网格在测量标签后优先预留23dp图标、12dp状态标记及4dp间距所需的图标面空间；宽松内边距不能继续挤占该空间。窄安全区压紧侧栏后，仍不足的格位按实际宽度限制图标，避免越界；高度不足时通过原正文滚动查看，不以压缩图标抵消大字号或双行标签。列数、四行网格视口及按钮数量无关的几何保持不变。网格与外层正文滚动各自通过 `FadingScrollView` 按实际视口渐隐，仅仍可向下滚动时启用，到达末行后停用；遮罩不随弹性内容位移，不叠加页面正文渐隐。紧凑媒体封面同时受卡片内宽及输出按钮占位限制。

- `PanelUi.controlContext` 从源资源复制显示配置后覆盖字体字段，不使用空配置覆盖来丢弃上游的密度、方向或尺寸；源显示配置变化时随控制页面重新创建。测试必须使用不同于宿主的密度并核对实际结果，不能只在宿主默认密度下验证字体隔离。

- `SystemControlCenter` 以本工具的 Binder 身份管理内外屏共用限制；`SystemControlGuard` 按显示、亮屏及连接事件恢复用户选择，取消操作优先于旧回调，不周期轮询。关闭选择只在本机保存，不随布局或配置导入导出。


## 原生卡片与双宿主启动器

- 空白组合卡片发布后的标题为“布置这张卡片(n)”，n 使用该卡片入口的固定编号1–6，与设置中的组合卡片编号一致，不使用三星宿主当前页序；说明下方以小字显示“(也可以在设置里面布置)”，不在错误提示卡片中显示该引导。

- 原生启动器普通应用在服务运行时通过非导出 Provider 的显式广播直接委托浮窗同一个 `CoverService.launchApp` 入口；服务未运行时调用共享 `AppLauncher`。不调用系统解锁、不设置锁屏上显示，不用中转 Activity 的屏幕或焦点、屏幕电源及 Keyguard 标记额外拦截普通启动，系统仍执行其自身锁屏策略。必须指定当前有效所选副屏、保留卡片身份和异步旧请求取消，不回退主屏；最近任务与系统动作保留既有保护。`AppLauncher` 的有界内存诊断并入复制结果入口，不保存应用身份、不持久化、不上传；详细边界见 [双宿主启动器](launcher-hosts.md)。

- `NativeWidgetProvider` 及其六个独立入口提供三星原生组合卡片；`NativeWidgetBridge` 负责授权实例、原子布局、RemoteViews转发与生命周期；`NativeWidgetActivity` 管理有会话身份的编辑草稿、系统授权和配置。`WidgetPickerView` 按应用分组展示预览与尺寸，`WidgetGrid`/`WidgetGridEditor` 管理每卡4×4内多个组件的无重叠格位。布局在完成时提交，取消只释放本会话新增实例；旧整卡绑定保持身份。仅使用所选副屏，绑定身份不进入布局导入导出；移除卡片释放其全部实例，息屏停止订阅，不截图转发、不自动授权。组合转发使用独立格位RemoteViews根，避免跨包资源ID冲突；`WidgetContentLayout` 在格位内等比适配固定尺寸组件并保留原生点击。原生组合卡片按状态栏及白条绘制边界预留，面板仍避让完整入口触摸区；XML尺寸测量不执行RemoteViews动作或创建集合订阅，尺寸缓存随实例释放。遵循三星锁屏规则，不能替代真机原生宿主兼容性验证。

- `LauncherWidgetProvider` 是独立的三星原生应用启动器卡片，不占用组合卡片入口。浮窗与卡片共用 `AppLauncherModel` 内容规则、`AppLauncherStyle` 与资源尺寸、`AppDockLayout` 容量及清理目标、`AppRecentTasks` 请求与身份校验、`AppLauncher` 显式启动；`Prefs`/`AppWorkspaceLayout` 是唯一持久数据。`LauncherWidgetBridge` 管理订阅与内存文件夹状态；两宿主桌面页码由 `Prefs.launcherPage` 持久保存并按系统启动次数失效，搜索和文件夹不覆盖桌面页码，不进入备份；独立浮窗 Dock 始终从屏幕下方上滑入场。`LauncherWidgetViews` 只适配 RemoteViews，`LauncherWidgetActivity` 处理用户点击后的生命周期与目标屏校验。卡片含应用、文件夹、独立侧栏、固定/最近/清理 Dock；编辑只显示原生短 Toast“如需编辑，请到浮窗启动器内操作。”。左右滑动留给三星宿主，应用页用紧凑按钮翻页；侧栏为原生竖向滚动列表，不设翻页箭头，与浮窗共用紧凑条目规格。应用列表两宿主统一固定横5竖3、每页15格；可用空间、字号和图标规格均不能自动增减行列或改变页内格位。两个启动器整体使用固定字号：浮窗限定自己的字体配置为1倍，原生RemoteViews文字使用dp；保持真实显示密度，不修改系统字号或全局`Ui`。卡片标题居中，次要动作和分页/Dock留白保持紧凑；集合点击在服务运行时使用显式广播模板、无服务时使用 Activity 模板，执行前验证当前侧栏成员、卡片身份和目标屏，系统操作复用服务权限。卡片不后台轮询任务，仅主动刷新或接收浮窗结果；取消会话不能接受迟到恢复结果，无目标清理不使有效列表失效。息屏/移除释放订阅及图标，系统拒绝启动不能回退主屏。后续启动器公共功能、数据与样式必须在共享层修改，并检查两个宿主；不能维护第二份偏好或仅更新浮窗。宿主差异与验证入口见 `docs/launcher-hosts.md`。

- `AppLauncherStyle` 是两种启动器公共布局参数与几何的唯一来源：网格格位、应用图标及标签、侧栏、Dock、文件夹表面/标题/3×3预览和打开后的成员尺寸均在此调整；圆角共用尺寸资源。两个宿主不得另存同义尺寸或重复计算公式。文件夹保留2×2逻辑占位，表面按占位宽高中较小的一边居中为正方形，不能随网格行高拉长；应用图标保持等宽高。

- 启动器安全边界必须匹配所选显示器的方向与尺寸；系统边衬改变也更新边界，保留真实强制 Home 区域，不将隐藏导航栏的旧边衬当作启动器留白。

- 白条与正文共享 `CoverWindowInsets` 选定的完整外屏边衬，优先使用经显示器、方向、尺寸、密度、缺口及全屏原点校验的面板宿主实测；首次不可用时回退最大窗口度量，不使用白条小窗口的零边衬覆盖整屏安全区。同几何输入法／临时未测量状态保留上次有效样本，真几何变化或会话结束丢弃；来源及原始值保留在既有诊断，不增加轮询或窗口。细节见 [界面卡片](interface-cards.md)。

- 180° 的应用中心、通知、控制与任务正文将可分配的上下空白平分；双白条只收紧绘制下方的空触摸尾部，保留绘制位置和从原起点向下滑入的入口。启动器 Dock 固定，应用区、侧栏和设置按钮同位移，两个宿主共用 `AppLauncherStyle`；页面尺寸与内容更新独立，其他方向不变。边界与验收见 `docs/interface-cards.md` 和 `docs/launcher-hosts.md`。

- 启动器不显示右上角多任务或关闭按钮，短搜索胶囊居中，排序在同一行右侧；侧栏在屏幕安全边界与应用区之间水平居中，内部四边留出4dp，设置按钮独立位于侧栏下方并间隔4dp，圆形直径等于32dp侧栏宽度且左右对齐，图标共用20dp规格；`LauncherSidebarView` 复用共享液态张力，设置图标起初完整显示于侧栏底部，随后随圆面向下拉出、形成液颈并分裂，最终恢复既有独立位置；仅改变绘制，不改变格位或触摸区域，并管理侧栏内容避让、胶囊裁切与边缘渐隐。文件夹绑定共享玻璃并在刷新时保留材质及颜色；`AppWorkspaceView` 的拖动预览保持挂载、同步材质坐标并在结束时释放。Dock保留整体玻璃，仅清理扫把取消独立玻璃按钮。共享尺寸仍由 `AppLauncherStyle` 管理；原生设置入口只显示既有编辑说明 Toast。浮窗手动收起必须同步移动 `InterfaceCard` 背板与正文，松手从实际位置继续向下退出。

- `AppWorkspaceView` 负责应用中心横向分页、至多三页视图、合并预览与单步布局撤销；`AppDragController` 负责拖拽、边缘翻页与取消；`AppWorkspaceLayout` 保存应用唯一归属、2×2文件夹占位及原子重排。中心悬停冻结目标，满1秒只生成预览，松手才保存；文件夹最多9项、不嵌套，剩1项还原为应用。`AppFolderTile` 绘制3×3预览，`AppFolderGrid` 负责打开后的成员排序与拖出交接，`AppWorkspaceTools` 管理同窗口二级面板和批量整理。布局几何仅在最终布局更新；旋转只投影已保存格位，父容器试测不能取消手势。手动布局独立于搜索和自动排序；取消、折叠、卸载和真实尺寸变化终止旧触摸及合并计时。Dock常驻最多4个，与桌面及文件夹成员互斥；`AppDockPlacement` 计算插入与归属迁移并提供统一常驻上限，`Prefs` 原子保存两边，显式搜索仍包含常驻应用。最近任务不接收落点，并以窄细线与常驻区分隔；完整目录变更作废旧撤销。操作说明见 `docs/app-workspace-folder-plan.md`。

- `AppSearchIndex` 提供有界、本地的名称／别名／拼音索引。应用中心角标只统计当前用户已授权、仍活动且非持续/分组汇总的通知；断连即清除，不等同于系统未读数，不持久化历史。别名、文件夹成员与颜色、布局锁定及显示偏好纳入配置与布局备份，导入先校验唯一归属、容量及多格重叠，再原子更新。


## 快捷栏、状态栏与显示器

- 安全区是所有助手界面的统一布局策略层：`SafeAreaManager` 将现有边衬机制作为自动实现，将四方向本机校准作为手动实现。本文系统边衬避让约定属于自动模式；手动模式用校准边界替代，真实缺口始终保留，绘制与触摸同步。入口、描边、旋转确认／恢复、数据隔离及验收见 [安全区契约](safe-area.md)。

- `Prefs.dockAutoReturnFirstPage` 是“自动回到第一页”的唯一持久来源，设置入口为“快捷栏与手势 → 按钮与布局”，默认开启。快捷栏可见且停留在非第一页时，停止操作5秒后回到第一页；新操作重新计时，触摸、滑动、长按及多指序列结束前不自动跳页。收起、隐藏、失焦、息屏及卸载取消旧计时，重新显示后开始新的等待，不后台轮询。开关局部同步到既有快捷栏，不重建窗口；关闭后保留当前页。配置及布局备份保存可选布尔值 `dockAutoReturnFirstPage`，缺省使用配置默认值，错误类型在提交前原子拒绝。默认开关与等待时长分别由 `app-config.json` 的 `defaults.dock.autoReturnFirstPage` 和 `motion.dock.autoReturnDelayMs` 管理。

- “选择自动隐藏的应用”排除 `com.android.systemui`（三星外屏与系统面板），默认名单仅保留三星 One UI 桌面。`Prefs.compactApps` 统一排除旧名单中的该包，偏好初始化清理已保存选择，配置导入也移除它；列表无论来自目录、默认项还是旧选择都不显示该包。首页由独立首页规则及模式控制，不再受这条系统界面隐藏规则影响；状态栏的独立应用名单保留原有选择能力。

- 首页强制收起或收起展开模式需要翻页监听，事件即时交付独立于应用自动隐藏开关及名单。仅所选外屏的 System UI 翻页事件或已确认首页窗口的状态事件可预隐藏快捷栏；首页目标需收起时先隐藏原按钮窗口，再允许原生应用中心两个入口解除禁用。中间窗口元数据未确认时保留预隐藏，落到首页后原位挂载收起箭头；跟随常驻或已展开模式不预隐藏。沿用现有一次稳定检查释放未确认的过渡，不新增后台轮询、节点读取、主屏回退或翻页状态持久化。

- 原生卡片“不可见”回调可能早于所有窗口和翻页事件。原来禁用的两个启动器入口在首页目标需要收起、目标页面尚未确认且按钮窗口仍显示时保留禁用状态；短暂失焦不能提前解禁。确认首页并隐藏按钮窗口后才恢复可用，确认普通应用或打开浮窗立即解除等待；切到其他原生卡片未能确认页面时复用原有600ms有界等待，超时释放且不重新续期。跟随常驻或已展开模式不延迟解除。息屏、窗口卸载和目标变化取消旧等待；诊断最多保留16条内存状态转换，不含应用身份，不落盘、不上传。

- 收起箭头以实际快捷栏绘制区域为唯一位置来源，沿用其真实缺口及用户导航避让设置，不因应用导航区再次裁切、变成零尺寸或额外上移。展开位置仍避让当前可见系统栏、强制手势、快捷按钮及双白条；不沿用已隐藏导航栏的旧边衬。保持按钮静止几何，不修改系统手势或全局导航策略；系统实际触摸路由须真机确认。

- `Prefs.dockExpandable` 是常驻／收起展开模式的唯一持久来源，设置开关与双白条长按写入同一个偏好；旧配置缺少该字段时使用常驻模式。`Prefs.clockFollowsDockRules` 是“首页跟随快捷栏规则”的唯一持久来源，默认关闭；模式与首页规则进入配置及布局备份，导入先校验布尔类型再原子提交，旧文件缺少首页规则时关闭。关闭时，两种模式每次进入已确认的三星时钟首页都强制收起，保留可点击且自动淡出的箭头；首页临时展开独立保存，离开首页清除并恢复其他页面原模式及展开状态。开启时，首页同步常驻／收起展开模式、会话展开状态、应用自动隐藏及常驻模式键盘避让，不享有名单例外。“按前台应用自动隐藏”沿用 `dock_auto_hide` 开关及 `dock_compact_apps` 名单，是一个功能；启用且确认命中名单时优先隐藏快捷栏与箭头，双白条保留。离开名单应用恢复原模式与展开状态，关闭开关或空名单停用应用判断。前台身份未知时不按名单隐藏，也不借用旧应用身份。键盘避让仅用于常驻模式。`DockVisibility` 保存当前亮屏会话展开状态，切应用、返回桌面、助手面板开关和同一显示器重建不能覆盖；首页按独立规则处理，切换首页规则只清除首页临时展开，不改写其他页面展开状态。进入收起展开模式、息屏、目标显示器变化及服务重启后从收起开始，模式本身不重置。`DockHandleView` 每次只挂载一个，助手面板／启动器打开时暂时移除，关闭后恢复。模式及箭头切换复用快捷按钮窗口，设置通过偏好监听局部同步，不重建设置页或改变滚动位置。系统真正锁定仍全部隐藏。

- 原生应用中心可见时，快捷栏的临时 Dock／应用中心入口保留原位，图标以30%透明度灰显，中央叠加与原生卡片一致的禁止符号；停用点击和长按，保留无障碍禁用说明，退出后恢复。可用快捷按钮点击复用 `ControlFeedback` 的缩放回弹，只变换绘制，不改变格位和触摸范围；滑动、取消、多指、禁用及卸载清除旧反馈。可见性条件与首次等待边界见 `docs/launcher-hosts.md`。

- 两种模式的时钟首页按所选外屏活动应用窗口元数据识别：System UI 包名或本地化窗口标题，排除 `SubLauncherWindow` 卡片，不读取页面节点。首页跟随关闭时，时钟首页不受应用自动隐藏名单及分页预隐藏覆盖；跟随开启时遵循名单，常驻模式没有额外箭头。首页上实际可见的收起箭头半透明等待3秒淡出，透明时仍可点击；其他页面收起后保持半透明可见，展开时始终可见。页面变化原位更新淡出策略；离开首页取消旧计时，返回首页恢复延迟淡出，展开状态按首页规则处理。切应用仅改变系统栏边衬时，在显示器身份、方向、尺寸、密度、缺口及快捷按钮局部几何不变且没有界面过渡的情况下，保留快捷栏、箭头、状态栏和双白条窗口，原位更新安全边界与布局；状态栏订阅、箭头透明度和淡出状态不中断。白条同步更新内部绘制位置并取消旧输入，箭头几何变化时取消旧动画并按展开状态落定；旋转、换屏、配置强制刷新或结构变化仍走重建。确需窗口重建、面板关闭或自动隐藏结束后，箭头按当前展开状态直接挂载到目标位置，不从屏幕外重新滑入；只有点击箭头切换展开状态才播放位移动画。箭头与快捷栏共用原有动画进度，快速反向从当前位置继续，移动期间快捷按钮不可触摸；点击重新校验所选亮起且已解锁的副屏。自动隐藏规则启用时窗口事件不合并延迟，System UI分页事件沿原有边界提前隐藏并有界确认落页，不读取页索引，不增加轮询。

- 三星半机姿态允许本应用保留原有窗口缺口策略，快捷栏仅使用真实缺口旁的可显示区域，正文继续服从共享安全边界；不修改系统姿态、全局导航策略或其他应用。原生卡片的窗口原点与助手悬浮窗独立，适配边界见 [半机与整屏宿主](launcher-hosts.md#半机与整屏宿主)。

- `Displays.selected` 自动识别使用显示器物理模式的尺寸，避免三星 Activity 分辨率缩放影响身份判断；`Displays.size` 继续服务运行时几何。手动选择优先，不回退主屏。原生卡片普通应用启动由 `CoverService.launchApp` 自行解析所选屏，不接受中转 Activity 预先解析的目标。

- `CoverService` 负责无障碍悬浮窗和显示器生命周期；`DockView` 负责快捷按钮点击、翻页及长按配置；`PanelEntryView` 独立负责双白条滑入、长按显隐及无障碍入口，按钮区不再打开面板。双白条始终横排：左条通知、右条控制中心。位置由 `Prefs` 按旋转方向独立保存：0° 仅左顶部或右底部，180° 固定左顶部，90°／270° 仅左顶部或右顶部；默认依次为右底部、左顶部、左顶部、右顶部。`DockGeometry` 统一计算入口及避让，设置预览复用同一计算；配置、布局备份和撤销校验合法组合后原子更新。顶部入口下滑、面板从上方跟手展开并向上收起；右底部入口上滑、面板从下方展开并向下收起。不得恢复侧边竖排入口；实测侧边 safe area 仍会触发三星返回。白条默认透明且触摸入口保留，滑入触发后从0淡入到1；面板打开期间保持100%，关闭后先淡到50%，等待3秒再淡到0；重开取消旧计时并恢复100%。只在白条可见时接受长按切换常驻／收起展开模式，隐藏时长按无效；无障碍显式动作保留。只绘制一组白条；多指、尺寸变化和卸载取消旧拖动与长按，控制中心编辑时入口不可触摸。设置页明确每个方向的可选位置、展开方向及避开 Home／返回手势的原因，不声称关闭系统手势。`ShellService` 负责受限的 Shizuku 命令白名单；`ShizukuBridge` 负责连接及后台调用。

- 常驻状态栏按应用显隐只作用于助手自绘的所选外屏状态栏；`Prefs.statusHiddenApps` 保存独立名单，`CoverService` 复用该屏窗口元数据及事件包名，`StatusAppVisibility` 管理有界切窗等待，无法确认时显示。状态栏及快捷按钮的应用名单为空时停用相应判断，共用补充监听按需启停；不得读取页面节点树、保存使用历史或控制任何原生系统栏。名单纳入配置与布局备份，控制中心状态行保持独立。

- `StatusBarView` 在系统向本应用报告可见 VPN 网络时自动显示横向钥匙图标，常驻栏与控制中心状态行共用；不要求 VPN 成为默认网络或具备互联网能力，不代表互联网连通性。通过只读 `TRANSPORT_VPN` 网络回调维护当前挂载会话，最后一个可见 VPN 断开后隐藏；卸载取消订阅并清空状态，旧回调不能恢复图标。沿用现有前景色、阴影、缩放及安全边界，不新增权限、后台轮询、系统状态栏控制或 VPN 操作；系统不可见的其他用户／工作资料 VPN 不推断为已连接。

- 前台窗口查询由 `CoverWindowQuery` 在独立单线程执行，启动、事件回调和窗口重挂载均不得在主线程调用 `getWindowsOnAllDisplays()`。同时只允许一次读取及一次合并的后续请求，不轮询，不因超时另开线程；系统窗口对象在后台复制为所选外屏的元数据后立即回收，主线程只应用结果。事件只保留至多32项窗口标识、类型与包名，不持有框架事件对象。息屏、锁屏、显示器移除、选择或几何变化及服务解绑使旧结果失效；回调再次校验服务会话、目标屏身份、尺寸、方向、亮屏和解锁状态，不能恢复旧界面或回退主屏。

- `StatusBarView` 负责状态订阅，并在视图移除时释放；`AppHubView` 负责应用中心、临时 Dock 的原位展开切换与可释放的视图订阅；`AppDockView` 负责两种状态共用的固定应用、按宽度显示的最近任务、清理及全部应用入口。`app_dock` 打开临时 Dock，`app_hub` 直接展开应用中心；应用启动请求被系统接受或最近任务确认恢复后关闭全部相关临时界面，失败保留界面与提示。`AppCatalogCache` 负责进程内应用目录和有界图标缓存，安装包和语言/密度/深浅色配置变化时失效，低内存时释放图标，只持有应用 Context。`DockVisibility` 统一应用自动隐藏优先级、常驻模式键盘避让和收起展开模式的会话状态。前台识别仅使用目标显示器的窗口元数据和事件包名，不读取页面节点树，不持久化应用历史。

- 应用旋转规则只在从本工具显式启动应用时执行，每次启动仅执行一次；异步 Shizuku 调用结束后重新检查目标显示器。不得通过前台窗口事件强制应用方向。左右手布局只调整既有安全范围内的控件顺序，不镜像摄像头缺口。

- 悬浮层默认通过透明表面和本地柔和阴影提高对比度，`ChromeShadowDrawable.forIcon` 是时间、电池、Wi-Fi、通知、充电及普通快捷图标共用的阴影参数入口，按尺寸及内容缓存透明度蒙版；时间或电量变化只更新对应缓存，不保留时间／电池独立的描边或扩展阴影。分页提示和双白条保持独立配方。保留手动浅色／深色图标与纯黑实底，沿用 `contrast` 偏好值兼容旧配置；不后台轮询截图，也不声称能读取其他应用的 SystemUI 外观或自动适应背景明暗。状态栏缩放范围为 50%–150%；控制面板与常驻栏采用同一左右布局：时间及通知在左、网络与电池在右；控制面板右侧始终显示电池百分比，不受常驻悬浮状态栏的显示设置影响。

- 快捷按钮沿用原位置及可选导航避让，收起时旧窗口不可见且不可触摸。独立双白条按所选显示器的真实缺口和强制 Home 边衬定位；未报告缺口时仅以已校准快捷栏的相邻区域推算，明确标记估计，不硬编码机型像素。状态栏与面板正文避让白条触摸区，不重复增加页脚。手势排除不能禁用系统强制 Home 手势，不得写入全局沉浸式或导航策略。`AppHubView` 与原生启动器共用固定5列3行应用网格，采用紧凑编辑控件，并保持常用区与固定区独立。


- 全屏实测随最大窗口边衬代次失效，布局回调不能重新授信旧样本；编辑延后及恢复规则见 `interface-cards.md`。白条几何诊断复用“问题诊断”的刷新与复制入口，分别显示最近窗口度量读取、实测事件时间和当前已应用布局：记录计算时的显示尺寸／方向／密度、Display 缺口、最大窗口度量、可见及忽略可见性的导航边衬、强制手势边衬、正文边界与白条请求窗口；布局完成后以窗口屏幕原点和当前绘制矩形记录实际位置。`CoverService` 保留最近12条不同几何快照，窗口卸载前保留末态，复制时另读当前状态；服务重建后清空，不记录应用身份或页面内容、不落盘或自动上传、不增加周期取样。诊断不改变定位、避让、手势和窗口层级，数据不可用须明确标注。

## 最近任务

- `system_recents` 通过固定的 Shizuku 白名单操作启动三星 `RecentsActivity`，传入所选副屏和应用所属用户；不再发送可能路由主屏的无障碍全局最近任务动作。请求及执行前后校验亮屏、解锁和目标，排队时会话失效则取消，迟到结果不得更新旧界面。失败明确提示，不回退主屏或自动打开自有任务页，不强停三星桌面、不延时重启进程；命令被接受不等于固件已正确显示，实际显示仍需真机验收。

- `RecentTasks` 负责内存中的应用分组和任务身份校验；`SystemRecentTasks` 通过 `ShellService` 适配特权系统任务接口。任务页读取所属用户的内屏、所选副屏及未挂载最近任务，保留来源 displayId（未挂载为 -1），排除其他副屏和其他用户；Dock 仍只读取和清理所选副屏任务。读取最多100项，不再额外截断到32项；达到上限标记列表不完整。基准 Intent 组件缺失时使用 baseActivity，仍无稳定组件则排除。移除前重新核验任务身份与来源，不能把移屏当作关闭成功。最近任务仅在临时 Dock、应用中心或任务页可见且已挂载时刷新，关闭和卸载后停止。固定应用最多四个，与侧栏常用应用独立；Dock最近区最多四个，空间不足时减少，完整任务页不受该数量限制。Dock 清理只包含当前可见最近应用对应的可清理任务；最近任务历史不持久化。

- `RecentTasksView` 是展开应用中心内的外屏任务页，按三张完整卡片并排确定尺寸，从右到左为从新到老，最新任务默认居中；横向连续跟手滚动并支持惯性，停止后必须有一张卡片弹性居中、不按三张分页；只挂载可见或将补位入场的至多4张卡片并回收复用，任意数量在首尾均可继续拖动并弹回边界，首尾及少于3张时也以单张卡片居中；高度按宽度确定并保留上下留白，不拉满可用高度；名称和锁置于预览外，卡片下方不显示状态文字；状态与操作语义保留在无障碍说明，一键清理×位于下方留白中央，不设独立底栏、不遮挡卡片。任意卡片点击恢复、上滑关闭、下滑锁定或解锁。单项上滑允许关闭列表中的内外屏固定及前台任务并保留固定入口；任务页×清理列表中全部未锁定任务（含内屏），Dock清理仍跳过固定和可见任务。显式关闭走`recent_dismiss`白名单，两种清理均保护任务锁并重新校验身份、显示器和用户，结果以系统返回为准，失败回弹；不扩大到包级强行停止，不保证所有服务进程结束。首次打开或普通刷新为空时保留任务页，居中显示“当前没有后台任务”；明确关闭最后一项成功后自动退出，失败与断连不算清空；×清理成功也自动退出。任务页恢复全屏玻璃卡片，统一从底部向上滑入、向下跟手收起；空白轻点关闭且不透传到底层应用。关闭仅复用仍有效的本次背景完成退场，来源失效后不能重新画出旧截图，完成后释放窗口与会话。`RecentTasks.Locks` 由 `CoverApp` 持有，仅在进程内按任务身份保护至多32项，任务页、最近Dock及清理提交共用；完整列表确认任务消失或发现身份变化后释放，不完整列表不能解锁遗漏项，不保证系统常驻。卡片手势独占命中区域，标题和空白区由 `PanelSurface` 收起。内屏任务名称后以小字标注“(内屏)”，仅显示应用图标，UI 和特权接口均不请求其截图；未挂载任务同样仅显示图标但不虚构内屏归属。卡片点击通过来源身份重新核验原 task ID，以所选外屏作为独立目标恢复，只有相同 ID、用户和组件在目标外屏可见才确认成功；失败保留页面，不重新启动 MAIN 或回退主屏。`recent_page` 为有界页面读取白名单，`recent_dismiss` 为显式列表关闭，原生卡片和浮窗 Dock 继续共用外屏读取；页面结果传给原生 Dock 前按实际选择或识别的外屏过滤。系统快照仅按需串行读取视口内的外屏任务，最多最近三项；已加载的256px预览按任务身份缓存至本次任务页关闭，左右滑回不重复读取，缓存至多32项。任务消失或身份变化释放对应缓存，关闭、断连和低内存时释放全部；后台只读取已有系统低分辨率快照，缺失再读正常缓存；当前可见任务按需调用一次系统任务快照并保留系统保护，使用updateCache=true，不截取整屏替代；临时失败至多重试一次，不可用或受保护时显示图标。`recents` 打开自有任务页，`system_recents` 是需要 Shizuku 的三星系统独立入口。

- `TaskForce` 负责任务页四张卡片、清理 × 和背景共六节点的弹簧受力；`RecentTasksView.Carousel` 统一驱动位移、预览形变和独立补位，入场与回弹的加减速传入同一受力图，大惯性吸附限制形变和回弹幅度；无手势且受力稳定后停帧，系统请求等待不单独驱动动画。逐任务关闭按身份排队提交既有 `recent_dismiss`，其他卡片保持可操作；系统确认且退场后移除，失败连续回弹，同帧移除保持可见位置。`TaskPreviewView` 只变形预览，`PanelGlassSession` 复用背景纹理产生反作用，不额外取样。契约与验证入口见 `docs/task-force.md`。

- 任务关闭的跟手与队列优先于背景特效：提交关闭可见任务、来源窗口消失或切换（包含同一三星宿主窗口内的 Home 页面切换）时先退役旧背景；确认新的底层窗口后，仅以窗口截图按切换事件更新一次玻璃，等待手势、关闭队列及补位稳定后提交纹理，不重建正文、不周期取样；同屏同尺寸任务会话内的导航边衬更新推迟到退出，真实显示器、方向、尺寸、密度变化及锁屏仍立即处理；关闭和补位期间暂停新增预览请求及迟到预览的显示，待稳定再恢复。资源与来源校验契约见 `docs/panel-glass.md`。

- 多任务入口直接创建无额外窗口压暗的任务卡片；`AppHubView` 通知页面导航，`CoverService` 协调单次入场与所选外屏，`InterfaceCard` 持有一次性背景会话并关闭重复窗口模糊；返回应用中心创建新启动器卡片，不复活已移出的界面。`TaskPreviewView` 是唯一的预览卡片表面，提供与页面背景相同圆角半径的矩形裁切与凸透镜；任务页持有并释放本次页面会话的任务快照缓存，名称、状态和锁定标记不折射。任务页统一从屏幕底部向上入场、向下收起，空白拖动、取消回弹和退出同步移动InterfaceCard背板及正文；卡片、清理槽、多指和长按不触发空白轻点。任务正文没有顶栏，任务页采用全屏透明液态玻璃背板，预览保留物理圆角，清理动作居中并共用控制中心 `PanelActionSlot` 小按钮规格；背景准备后立即恢复预览请求，不能等待周期刷新。材质与验证入口见 `docs/panel-glass.md`。


## 界面卡片、手势与玻璃动效

- 通知中心在左、控制中心在右：一级通知页左滑进入控制页，一级控制页右滑进入通知页。固定窗口宿主 `PanelHost` 统一仲裁并持有完整横滑序列；通知卡片、横向滑条及其他自有横向控件优先，普通按钮、媒体卡、纵向列表和竖向亮度／音量条在横向意图明确后可切页，接管前取消子控件点击及数值提交。先确认为纵向的序列不得再转切页；详情、编辑及多指不切页。按下和方向未明时不预加载，第一次有效横滑才由 `CoverService` 创建目标 `InterfaceCard`，后续移动只更新两页位移；同次横滑不重复构建、取样或读取状态。未提交时最多保留当前两页用于回弹，提交后旧页退出即释放，取消释放目标页并恢复原页；关闭、Home、息屏、失焦、尺寸及目标显示器变化终止旧序列。切换结束后恢复白条所在方向的纵向收起。实现及验收入口见 `interface-cards.md`。

- `PanelSurface` 统一负责标题、空白区和滚动边界的面板收起手势，保护滑条及输入操作，并在取消或视图移除时回收速度跟踪器。通知中心由 `NotificationScrollView` 提供上下边界的弹性位移与卡片拉伸；必须先滑完卡片列表，到收起方向对应的边界后继续拖出的弹性距离才计入阈值，正常列表滚动与旧回弹不累计。越界距离超过 `PanelSurface` 定义的阈值时立即接管，整个通知中心跟手移动；任意触摸落点均遵守同一列表边界条件，取消、多指及尺寸变化终止手势，横向通知操作保持独占；`Prefs` 在一次原子偏好更新前验证布局快照。恢复布局必须保留显示器选择、权限和系统显示设置。Gradle 应用产物及报告位于 `Cache/build-output.nosync/app/`。

- `RuntimeVisuals` 仅为主动接入的运行时控件提供绘制反馈，不修改共享 `Ui` 或设置主题。运行时视觉和动效改动必须保持既有静止尺寸、位置、间距、字号与触摸范围；多指序列由运行时公共容器在子控件事件拆分前取消。

- `ControlScrollView` 管理正常控制中心网格的原生滚动与唯一 `ControlElastic` 一维弹簧：先滚到边界，再拉网格，到限后传给 `InterfaceCard` 整页绘制拉伸，松手同时恢复。`ControlFeedback` 提供有限按压、滑条方向位移及固定局部余弹；不建立逐模块受力网络，不修改布局或命中范围。材质沿绘制矩阵复用 `PanelGlassSession`；稳定、取消、卸载及关闭系统动画时停止动效，编辑页不接入。契约见 `docs/control-force-design.md`。

- `LauncherForce` 以固定八区域节点驱动浮窗启动器，`AppHubView` 持有唯一受力帧回调，`LauncherMotionLayout` 与各区域仅变换绘制；不增加逐图标物理状态，稳定、隐藏及卸载后停帧。顶部搜索、排序与摘要共用一个节点；`LauncherSidebarView` 独占固定延时分裂及滚动边界反馈，复用既有玻璃纹理。契约及双宿主边界见 `docs/launcher-force-design.md`。

- 启动器内部表面按 `AppLauncherStyle.SURFACE_INSET` 避让外层背板；分页仅以实际位移差注入受力，停帧保留按住时的全图平衡，玻璃取样包含绘制位移。`AppWorkspaceTools` 的文件夹与管理菜单去除关闭按钮、在同卡片空白关闭，尺寸由共享样式管理，弹簧复用 `DetailSheetMotion`；`AppDockView` 持有一次有界入场时钟，绘制胶囊后错开弹出两端动作，卸载取消。

- `LiquidTensionSurface` / `LiquidTensionRenderer` 是 Liquid Glass 的共享张力扩展，Compose 与原生 View 共用组级轮廓；通知由 `NotificationSwipeRow` 提供可见卡片与按钮，按最先露出的顺序分裂，前一按钮完全断开后才分裂下一按钮，回滑反向融合；`PanelGlassSession` 复用既有纹理并释放缓存，不改变独立控件的触摸或语义。复用及性能边界见 `docs/liquid-tension.md`。

- `PanelActionHeader` 统一负责通知与控制中心顶栏从右向左的顺序液态分裂，仅变换绘制并复用本次玻璃纹理；静止材质、反馈、按钮格位、字号与命中范围保持原样。顶栏触摸先结束入场，尺寸变化、隐藏与卸载取消计时；实现与验证入口见 `docs/liquid-tension.md`。

- `CoverService` 在快捷栏下方保留覆盖整个显示区域的面板宿主，关闭时不可见且不可触摸。内容使用管理器给出的页面与正文边界；快捷栏绘制和触摸区始终位于页面外，不能再扣减正文宽高，不重复预留触摸区页脚。控制页的面板状态行替代常驻悬浮状态行。组件预览复用同一面板内容构建器，但不能证明三星系统的窗口路由行为。

- `InterfaceCard` 是通知、控制、任务与浮窗启动器共用的界面卡片容器，统一玻璃背板、进出位置、触摸交接与释放；`Definition.material` 只在透明／磨砂间选择，当前仅控制中心磨砂；`Definition.useSafeArea` 与 `Definition.useCardSafeArea` 分别决定正文避让和背板安全范围，现有四页均开启安全正文及页面背板；玻璃模糊、圆角和渐隐跟随页面边界，正文再独立扣除入口预留，原始窗口与取样尺寸不变；详情、文件夹、操作菜单和输入面板通过管理器映射到所属内容边界，设置缩放与已内缩父容器不能重复扣边。`Definition.showStatusBar` 决定容器创建、留白及释放顶部状态栏，当前仅控制中心开启，编辑期间卸载。启动器内部侧栏、应用区和独立 Dock 各自保留透明液态玻璃表面与既有几何，借用本卡片背景，不重复取样。快捷图标打开启动器也从屏幕外滑入。四种卡片沿新界面的划入方向互相推移，初始短插值连续跨过入口前的不安全区，旧卡片保持安全页面轮廓让位，之后按实际手指位移跟随；视口与正文测量不在动画中改变。旧卡片滑出立即释放，不保留返回栈；通知／控制横滑未松手时暂时保留本次旧页，允许拖回取消，松手提交后按退场释放。旧界面过渡期间不可触摸，双白条保持挂载，控制中心编辑期间仍禁用入口。扩展契约见 `docs/interface-cards.md`。

- `CoverService` 的两个启动器宿主须先于状态栏、快捷栏和双白条挂载；Dock 开关不得重挂这些顶层控件。关闭释放卡片内容并隐藏空宿主，显示器生命周期结束才移除宿主；契约见 `docs/interface-cards.md`。


## 通知、媒体与详情

- 通知卡片关闭状态右滑超过卡片宽度30%立即请求清除，不等松手，不用速度替代距离；未过阈值回弹，已展开操作时本次右滑只收起。单项／分组头分别沿用单条／该组可清除成员的范围，不可清除通知不提交；收到系统确认后才向右移除，失败或身份变化恢复，取消与旧序列不触发替换通知。左滑操作保持原语义，细节见 [通知交互](liquid-tension.md#通知交互)。

- 通知事件只刷新既有 `Panels` 容器中按键标识对应的行，不得为内容更新重新打开或重建面板窗口。可见内容未改变时不重设文字或滚动位置；持续更新的既有通知保持原行位置。

- `MediaSessions` 在媒体表面可见时订阅系统会话；`MediaCardView` 和 `MediaDetailView` 卸载时退订，最后一个表面卸载后释放会话回调。仅展开的媒体详情每秒推算一次进度，不轮询媒体元数据或下载封面。

- `DetailSheet` 统一负责二级弹窗的内容尺寸测量与动画，只有正文列表滚动；`ControlDetails` 负责按钮详情并在关闭时释放媒体回调。系统选择器保留系统布局。`CoverRotation` 是方向传感器的唯一控制者，手动选角度和显式应用方向规则会停止它，只能作用于所选外屏。

- 通过 `TileService` 发现 Android 快捷设置磁贴；执行能力属于实验性质，不得虚构状态。三星 `com.samsung.android.lool/com.samsung.android.sm.battery.ui.mode.BatteryModeTile` 的省电状态直接读取 `PowerManager.isPowerSaveMode()`，与诊断及玻璃启用判断一致；打开控制中心时回读，系统省电广播到达后原位更新当前按钮，不重建窗口、不轮询。按完整组件身份适配，不按名称或图标推测其他磁贴的状态；点击仍走既有受限磁贴请求，未确认的请求不能提前显示成功。应用权限始终由用户控制。
